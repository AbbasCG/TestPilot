## ثالثًا: نفّذ M3 بالكامل — Test Scenario Management

هذه أولويتك الرئيسية الآن.

أريد تنفيذ نظام كامل يتيح للمستخدم إنشاء الاختبارات وإدارتها دون كتابة شيفرة.

### 1. Test Suites

- إنشاء مجموعة اختبارات.
- تعديلها.
- ترتيبها.
- أرشفتها.
- ربطها بمشروع.
- إظهار عدد السيناريوهات وحالتها.

### 2. Test Cases

لكل سيناريو:

- ID فريد.
- العنوان.
- الوصف.
- الهدف.
- الأولوية.
- نوع الاختبار.
- المتطلبات المسبقة.
- الحساب المطلوب.
- الدور المطلوب.
- البيئة.
- البيانات التجريبية.
- النتائج المتوقعة.
- معايير القبول.
- الاعتماديات.
- الحالة.
- الإصدار.

### 3. Scenario Builder

أنشئ محررًا بصريًا احترافيًا يدعم:

- إضافة خطوة.
- حذف خطوة.
- تعديل خطوة.
- إعادة ترتيب الخطوات.
- تحديد المختبر المسؤول.
- إضافة رابط الصفحة.
- تحديد الزر أو الحقل.
- إضافة قيمة اختبار.
- كتابة النتيجة المتوقعة.
- إضافة تعليمات تفصيلية.
- إضافة نقطة تحقق مشتركة.
- إضافة دليل مطلوب.
- ربط خطوة بأخرى.

أنواع الخطوات:

- Navigate.
- Click.
- Input.
- Select.
- Upload.
- Verify.
- Compare.
- Switch User.
- Wait For Tester.
- Shared Checkpoint.
- Capture Evidence.
- Custom Action.

لا أريد محررًا تجريبيًا لا يحفظ البيانات.

كل شيء يجب أن يعمل عبر API وقاعدة البيانات.

### 4. Versioning

عند تعديل سيناريو مستخدم في جلسة اختبار سابقة، احتفظ بتاريخ النسخة السابقة.

لا تغيّر نتائج الاختبارات التاريخية عند تعديل خطوات السيناريو.

### 5. Templates

أنشئ قوالب عامة قابلة لإعادة الاستخدام:

- تسجيل حساب.
- تسجيل الدخول.
- إنشاء سجل.
- تعديل سجل.
- حذف سجل.
- إرسال دعوة.
- قبول دعوة.
- اختبار صلاحيات.
- اختبار عزل بيانات.
- اختبار سير عمل بين شخصين.

## رابعًا: نفّذ M4 — Collaborative Testing

بعد اجتياز اختبارات M3، نفذ الاختبار التعاوني.

أريد أن يستطيع مختبران تنفيذ نفس السيناريو من جهازين مختلفين.

### Test Run Creation

المستخدم يستطيع:

1. اختيار المشروع.
2. اختيار مجموعة الاختبارات.
3. اختيار السيناريوهات.
4. تحديد البيئة والإصدار.
5. تعيين Tester A.
6. تعيين Tester B.
7. بدء الجلسة.

### Collaborative Runner

أنشئ واجهة تعرض:

- عنوان الاختبار.
- الهدف.
- المتطلبات المسبقة.
- خطوات Tester A.
- خطوات Tester B.
- التقدم.
- الحالة.
- النتائج المتوقعة.
- الملاحظات.
- نقاط التحقق المشتركة.

لكل مختبر حساب مستقل، ولا يستطيع تأكيد خطوات الشخص الآخر دون تصريح محدد.

### Shared Checkpoints

مثال:

Tester A:
- أنشأ دعوة معلّم.
- أكد ظهور الدعوة.

Tester B:
- قبل الدعوة.
- أكد ظهور المؤسسة.

بعد ذلك تظهر نقطة التحقق المشتركة:

هل أصبح المعلّم عضوًا في المؤسسة بالدور الصحيح؟

يجب حفظ تأكيد كل طرف بصورة مستقلة.

لا يعتبر الاختبار ناجحًا تلقائيًا لمجرد تحديد جميع مربعات الاختيار.

### Persistence & Synchronization

- حفظ التقدم.
- الاستئناف.
- Pause / Resume.
- منع الكتابات المتعارضة.
- Activity Log.
- تحديث حالة الطرف الآخر.
- إمكانية استخدام Polling إذا لم يتوفر Real-Time Server.

أنشئ End-to-End Test حقيقيًا بين حسابين مستقلين.
