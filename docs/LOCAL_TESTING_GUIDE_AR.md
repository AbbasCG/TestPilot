# دليل التجربة المحلية بمتصفحين — TestPilot

الهدف: تجربة حقيقية كاملة على جهازك بحسابين مستقلين، تمر بهذا التسلسل: مشروع ← سيناريو ← جلسة بمختبرين ← فشل ← مشكلة ← لقطة شاشة ← إصلاح ← إعادة اختبار ← تقرير.

كل الأوامر من داخل `D:\Projects\TestPilot` في PowerShell. لا يعدّل أي شيء هنا ثراء أو XAMPP أو أي مشروع آخر.

## 1. قاعدة البيانات

```powershell
.\infra\dev-db.ps1 start
```

- تعمل PostgreSQL 18 الخاصة بالمشروع على `127.0.0.1:55432`. قاعدة التطوير اسمها `testpilot`.
- لا تستخدم `testpilot_test` ولا `testpilot_e2e`؛ هما للاختبارات الآلية فقط.
- التحقق من أن كل الـMigrations مطبقة: نفّذ الأمر التالي داخل `backend`، ويجب أن تكون كل السطور `Ran`.

```powershell
php artisan migrate:status
```

- عند وجود Migration جديدة: خذ نسخة احتياطية أولًا (القسم 9)، ثم نفّذ `php artisan migrate`.
- لا تستخدم أبدًا `migrate:fresh` أو `db:wipe` على قاعدة التطوير.

## 2. تشغيل Laravel

نافذة PowerShell أولى:

```powershell
cd backend
$env:PHP_INI_SCAN_DIR = "D:\Projects\TestPilot\infra\php-local"
php artisan serve --host=127.0.0.1 --port=8000
```

- السطر الثاني يرفع حد رفع الملفات المحلي إلى 42MB لهذه النافذة فقط، دون تعديل `php.ini` الخاص بـXAMPP.
- من دونه يتوقف الرفع عند 2MB، فتفشل الفيديوهات والصور الكبيرة.
- تأكد من عمل الخادم بفتح `http://127.0.0.1:8000/api/health`.

اختياري، في نافذتين إضافيتين: `php artisan queue:work --tries=3 --timeout=60` و`php artisan schedule:work`. الوظائف الحالية لا تحتاجهما للتجربة.

## 3. تشغيل React

نافذة PowerShell ثانية:

```powershell
cd frontend
npm run dev
```

- افتح `http://127.0.0.1:5173`.
- استخدم `127.0.0.1` دائمًا، وليس `localhost`، كي تعمل ملفات الجلسة وحماية CSRF.

## 4. إنشاء الحسابين

**منذ 2026-11-13:** أنشئ حسابك فقط من سطر الأوامر كأول مالك للمنصة:

```powershell
php artisan testpilot:user you@example.com --name="اسمك" --platform-role=owner
```

ثم أضف المختبر الثاني من «إدارة المستخدمين»، بدعوة أو بكلمة مرور مؤقتة. التفاصيل في [USER_MANAGEMENT_GUIDE_AR.md](USER_MANAGEMENT_GUIDE_AR.md). الطريقة القديمة أدناه ما زالت تعمل.


لا توجد صفحة تسجيل ولا كلمات مرور افتراضية. الحسابات تُنشأ من سطر الأوامر، وكلمة المرور تُكتب مخفية ولا تُحفظ في السجلات:

```powershell
cd backend
php artisan testpilot:user owner@your-domain.example --name="اسمك"
php artisan testpilot:user tester@your-domain.example --name="اسم المختبر الثاني"
```

- كل أمر يطلب كلمة مرور من 12 حرفًا على الأقل، وتُخزّن مشفّرة (hash).
- الصلاحيات في TestPilot لكل مشروع على حدة، ولا يوجد دور «مالك منصة» عام.
- من ينشئ مشروعًا أو يستورده يصبح **مالكه**، وله كل الصلاحيات: الأعضاء، الإعدادات، سير عمل المشكلات، إغلاقها، الاعتماد النهائي.
- لاحقًا يضيف المالك الآخرين بأدوار: مدير، أو مختبر، أو مشاهد.


- 6 مجموعات و13 سيناريو، منها `TEST-TEACHER-001`.
- المشكلة المعروفة `[THR-AUD-143]` بحالة «مفروزة» (غير محلولة).

الأمر:

- لا ينشئ حسابات.
- لا يتصل بثراء ولا بقاعدة بياناتها.

## 6. المتصفحان

- **المتصفح الأول**، مثلًا Chrome: ادخل بحساب المالك.
- **المتصفح الثاني**، مثلًا Edge أو Firefox أو نافذة خاصة: ادخل بحساب المختبر.

لا تستخدم تبويبين في النافذة نفسها، لأنهما يتشاركان الجلسة نفسها.

## 7. سيناريو التجربة الكاملة

1. **المالك، إضافة المختبر:** من المشروع ← «أعضاء الفريق» ← بريد المختبر ← الصلاحية «مختبر» ← «حفظ العضوية».
2. **المالك، السيناريو:** استخدم أحد سيناريوهات ثراء الجاهزة (مثل TEST-TEACHER-001)، أو: «الاختبارات» ← «إنشاء مجموعة» ← «سيناريو جديد» ← قالب «سير عمل بين شخصين» ← الحالة «جاهز للاختبار» ← «حفظ السيناريو».
3. **المالك، الجلسة:** «جلسات الاختبار» ← «جلسة جديدة» ← العنوان، والإصدار (مثل `v1.0.0`)، والبيئة ← Tester A حسابك، وTester B المختبر ← اختر السيناريو ← «بدء الجلسة».
4. **المختبر:** يفتح الجلسة نفسها من «جلسات الاختبار». تتحدث نتائج الطرف الآخر كل 3 ثوانٍ.
5. **تنفيذ الخطوات:** كل طرف يسجل خطواته فقط: النتيجة، والنتيجة الفعلية، ثم «تحققت فعليًا…»، ثم «حفظ نتيجة الخطوة». نقطة التحقق المشتركة تحتاج تأكيد الطرفين، كلٌ على حدة.
6. **تسجيل فشل:** في إحدى الخطوات اختر «فاشلة»، واكتب ما حدث، ثم احفظ.
7. **إنشاء مشكلة:** في بطاقة الخطوة الفاشلة اضغط «إنشاء مشكلة من هذه النتيجة». تُعبّأ تلقائيًا خطوات إعادة الإنتاج والنتيجة المتوقعة والفعلية والإصدار. أكمل الوصف والخطورة، ثم «إنشاء المشكلة».
8. **رفع لقطة شاشة:** في صفحة المشكلة ← «الأدلة» ← النوع «لقطة شاشة» ← اختر صورة PNG أو JPG ← «رفع الدليل». تظهر الصورة في المعرض، وتُحفظ بشكل خاص؛ لا رابط عام لها.
9. **إصلاح تجريبي (المالك):** في «سير العمل»، طبّق بالترتيب:
   - «اعتماد الفرز».
   - «إسناد للإصلاح»: اختر نفسك.
   - «بدء الإصلاح».
   - «إرسال لإعادة الاختبار»: اكتب إصدار الإصلاح (مثل `v1.0.1`) ووصفه، واختر المختبر الثاني.

   لا يمكن أن يعيد الاختبار من أصلح المشكلة أو من طلب إعادة الاختبار.
10. **إعادة الاختبار (المختبر):** تظهر في لوحة المشكلات «إعادة اختبار مطلوبة منك» ← «تنفيذ إعادة الاختبار» ← أرفق دليلًا ← النتيجة والنتيجة الفعلية ← «نفّذت الخطوات فعليًا…» ← حفظ.
    - النجاح يحول المشكلة إلى «متحقَّق من إصلاحها».
    - الفشل يعيد فتحها.
11. **الإغلاق والاعتماد (المالك):**
    - «إغلاق المشكلة».
    - ثم في الجلسة ← «التقييم النهائي للجلسة» ← اختر التقييم واكتب الخلاصة ← اعتماد.
    - النتيجة الأصلية للجلسة تبقى «فاشلة» كما سُجلت، والإصلاح مثبت بمحاولة إعادة الاختبار.
12. **التقرير:** «التحليلات» تعرض نسبة النجاح وجاهزية الإصدار والاتجاهات وإنتاجية المختبرين.
    - التصدير: CSV أو JSON أو Markdown.
    - الـPDF: «تقرير قابل للطباعة / PDF» ← «طباعة أو حفظ PDF» ← في نافذة الطباعة اختر «Save as PDF».

## 8. مشكلات شائعة

| العرض | السبب والحل |
|---|---|
| خطأ 419 أو انتهاء الجلسة | تأكد أن العنوان `127.0.0.1:5173` في المتصفحين، وأن الخادم يعمل على 8000 |
| «تعذّر رفع الملف» للملفات الكبيرة | شغّل Laravel بالسطر `$env:PHP_INI_SCAN_DIR=...` (القسم 2) |
| 429 «Too Many Attempts» عند الدخول | تجاوزت 5 محاولات دخول في الدقيقة لنفس البريد. انتظر دقيقة |
| لا تظهر خطوات Tester B | تأكد أن الحساب الثاني هو المختار Tester B في الجلسة، وأنه عضو بدور غير «مشاهد» |
| «الجلسة متوقفة أو منتهية» | استأنف الجلسة من زر «استئناف الجلسة» |

## 9. نسخ احتياطية للتطوير

قبل أي Migration أو تجربة خطرة، من داخل `D:\Projects\TestPilot` في Git Bash:

```bash
set -a; . ./.local/database.env; set +a; export PGPASSWORD="$DB_PASSWORD"
"/c/Program Files/PostgreSQL/18/bin/pg_dump" -h 127.0.0.1 -p 55432 -U "$DB_USERNAME" -d testpilot -Fc -f ".local/backups/db/testpilot-$(date -u +%Y%m%dT%H%M%SZ).dump"
```

ملفات الأدلة المرفوعة محلياً موجودة في `backend/storage/app/private/evidence`. انسخها مع النسخة الاحتياطية إن أردت حفظها.
